# INSTRUCTION.md — ENTROPY Stage 1 MUSIC: Native Engine + Windows Virtual Render Ingress

**Destinatar:** Codex (implementare locală Windows / MSVC / WDK).  
**Obiectiv:** reconstruirea curată a Stage 1 pentru **MUSIC + AUX exclusiv**, fără componente CINEMA, cu procesare FP64/192 kHz și motor C++ complet separat de Qt. Proiectarea / implementarea noului endpoint virtual este un **proiect de driver separat**, conectat printr-un ABI definit, nu parte din procesul audio Stage 1.

> **IMPORTANT — constrângere Windows:** Un executabil user-mode Stage 1 **nu poate înregistra singur, doar prin WASAPI, un dispozitiv de redare virtual WASAPI Exclusive** pe care TIDAL/Spotify să-l vadă precum un DAC. Este necesar un dispozitiv/driver audio înregistrat în sistem (sau reutilizarea unuia existent). WASAPI este API-ul utilizat de player; sub acesta, un dispozitiv WaveRT folosește obligatoriu infrastructura audio Windows/PortCls/KS. **Nu** implementa un *client Direct WDM-KS* sau MME ca rută de intrare Stage 1; nici nu promite „kernel fără KS”, lucru incompatibil cu această arhitectură Windows.

## 1. Contextul problemei — observații reale, NU cauze demonstrate

Experimentele utilizatorului cu TIDAL arată:

1. **Shared / Exclusive OFF:** scena stereo, vocea, atacul și mediile/mediile joase sunt mult mai naturale. Way 1 nu mai prezintă cârâiturile caracteristice.
2. **Exclusive ON:** toate cele trei drivere existente (Private Tap, Entropy Music Transport, Entropy AUX) prezintă degradare majoră a dinamicii și spațialității; medii joase înfundate, voce retrasă, uneori cârâit. Gradul degradării diferă în funcție de material și format.
3. TIDAL selectează rata nativă acceptată de dispozitiv când este în Exclusive; comportamentul observat pe DAC-uri fizice a fost semnificativ mai bun decât pe traseul virtual actual.
4. Pe **Music Transport**, sliderul de volum TIDAL dispare atât în Shared, cât și în Exclusive; **Force Volume este OFF**. Pe AUX apare, iar în Exclusive poate rămâne afișat fără a modifica efectiv nivelul. Acesta este un simptom de capabilități/control al endpointului, **nu dovada că samples PCM sunt greșiți**.
5. MUSIC și AUX au, prin proiect, drivere/intrări/SRC-uri independente; sunt reunite numai în Matrix/Program, fără legătură cu CINEMA. Headroom este BITPERFECT și **nu face obiectul acestei intervenții**.

**Ipoteze prioritare de izolat, nu „fixuri” prestabilite:**

- cursor/clock virtual WaveRT necoerent cu mărimea pachetelor și completarea reală a bufferului;
- `SetWritePacket()` versus `UpdatePosition()` folosite greșit: citire înainte de completare, duplicate, blocuri vechi, rotație DMA sau gap-uri;
- negociere/interpretare `WAVEFORMATEX` / `WAVEFORMATEXTENSIBLE`, subtype PCM vs IEEE_FLOAT, `nBlockAlign`, container 16/24/32, `validBits`, channel mask;
- reconfigurare incompletă a SRC/FIFO la schimbarea ratei/generației streamului;
- identități și capabilități diferite între drivere, precum și datele de volum/RAW raportate către Windows.

**Precedent documentat:** `docs/Beta2/tidal-bridge-packet-integrity.md` din A06 consemnează un defect de calitate la transportul TIDAL legat de proprietatea asupra pachetelor WaveRT. Nu presupune că exact acel bug persistă în binarul instalat; verifică istoria și versiunea activă.

             │

             │                  (pentru comparație, prin adaptoare separate)
             ▼
       MUSIC SRC (r8brain existent) ──► FP64 / 192 kHz / L,R
                                             │
   AUX DRIVER / Windows capture eligibil ──► AUX SRC (instanță separată)
                                             │
                         INPUT MATRIX / PROGRAM L,R
                      (mixul MUSIC+AUX numai conform selecției)
                                             │
                          PUBLISHER PASIV MUSIC L/R
                                             │

                                             │

**Independență:** Stage 1 produce continuu chiar dacă Stage 2/3 sunt oprite. Stage 2 este consumator pasiv; nu conduce clockul sau lifecycle-ul Stage 1. Driverul V2 este independent de pornirea Qt și de disponibilitatea Stage 2/3.

## 3. Reconstrucția Stage 1 — implementare obligatorie

### 3.1 Procese, directoare, ownership

Structură logică nouă (numele exacte pot fi ajustate, dar nu responsabilitățile):

```text
Stage1-Music/
  Engine/
    Core/         EngineLifecycle.cpp/.h, Scheduler.cpp/.h
    Ingress/      WindowsEndpointCatalog.cpp/.h, SourceSelector.cpp/.h,
                  IEndpointProvider.h, PcmDecode.cpp/.h, ProviderAdapter.cpp/.h
    SRC/          MusicSrc.cpp/.h, AuxSrc.cpp/.h  [reutilizare r8brain existent]
    Matrix/       InputMatrix.cpp/.h, ProgramMixer.cpp/.h
    Transport/    InputFifo.cpp/.h, MusicPublisher.cpp/.h
    IPC/          Stage1ControlServer.cpp/.h, Telemetry.cpp/.h
  UI/Qt/          aplicație client IPC separată
  ABI/            endpoint_provider_v2.h, music_stage_publish_v1.h
  docs/           CONTRACT.md, FORMAT_MATRIX.md, LIVE-RESULT.md

Entropy-Music-Render-V2/      [PROIECT WDK SEPARAT; nu dependență de link a engine-ului]
  Driver/        miniport WaveRT, clock, ring, metadate, INF
  UserAdapter/   adaptor transport raw PCM → C ABI Stage 1
```

- Motorul audio și UI sunt **două executabile distincte**. Closing/restarting Qt nu oprește audio.
- Pregătirea bufferelor, instanțierea SRC, schimbările de format se fac exclusiv în control/worker non-real-time. Fără alocări, mutexuri blocante, log per-sample ori I/O filesystem în procesarea audio.
- `EngineLifecycle` nu deschide DAC fizic și nu controlează Stage 2/3. `MusicPublisher` este write-only pentru Stage 1; lipsa unui consumator nu oprește sursa.
- Salvează ultimul `WindowsEndpointId`/ProviderId ales doar în configurare, verifică prezența la start și afișează `UNAVAILABLE` dacă lipsește; **niciun fallback automat**.

### 3.2 Enumerarea Windows și selectorul MUSIC

- Folosește `IMMDeviceEnumerator::EnumAudioEndpoints(eRender/eCapture, ...)`, `IMMNotificationClient` și ID-uri persistente obținute din `IMMDevice::GetId()`. Afișează denumire, flux (render/capture), stare, identitate driver/provider, formate suportate/negociate și eligibilitatea ca **ingress**.
- **Distincție critică:** un endpoint `eRender` (DAC obișnuit) este o destinație pentru TIDAL, **nu o sursă de samples pe care Stage 1 o poate citi în WASAPI Exclusive**. Doar un endpoint virtual Entropy cu bridge/adaptor propriu poate livra acel flux Stage 1. Un endpoint `eCapture` poate fi citit cu `IAudioCaptureClient` dacă este selectat și acceptat. Loopback pentru un `eRender` generic funcționează doar în Shared și **nu reprezintă soluție pentru TIDAL Exclusive**.
- Selectorul MUSIC oferă un **singur ingress activ**: Private Tap / Music Transport / V2 (descoperite prin catalog, nu enumerate din array hardcodat). Nu prelua simultan același stream prin două rute și nu face downmix sau compensare pentru a „repara” stereo.
- AUX este **domeniu separat** cu propriul driver sau captură Windows eligibilă, FIFO și SRC. Expunerea lui în Qt nu trebuie să selecteze sau să reseteze MUSIC.
- Permite programul stereo rezultat `MUSIC + AUX` **doar conform stării Matrix**, cu nivelele originale, fără auto-normalizare; AUX mut/off nu trebuie să modifice MUSIC.

### 3.3 SRC / Matrix / Publisher

- Refolosește implementarea **r8brain HQ FP64** existentă pentru MUSIC și AUX; două instanțe complet separate (inclusiv history/state), canalele L/R separate; fără WDL pentru MUSIC prin substituție tacită, fără SOXR, fără rescrierea algoritmului.
- `Fs_in` vine **exclusiv din formatul negociat și raportat de provider**, niciodată din rata nominală a aplicației sau din ritmul apelurilor. `Fs_out = 192000`, FP64. La `Fs_in=192000`, copy stereo exact când procesarea este în bypass de SRC.
- Pe schimbare **source_generation/format/subtype/channel layout**: invalidează pachetele vechi, golește FIFO al acelei surse, reconfigurează SRC în afara threadului audio, setează discontinuitate explicită. Nu procesa în același bloc două rate/generații.
- Matrix MUSIC+AUX: stereo L/R identic ca intenție cu referința; niciun canal CINEMA, nicio sumă neintenționată între surse, niciun „stereo enhancer”. Output **exact două canale Program L/R** către Stage 2 MUSIC.
- `MusicPublisher` are sesiune, versiune ABI, block sequence, first frame, QPC, source generations, source validity și discontinuity. Nu mai emite `MIX_CINEMA10_V1`/10 canale. ABI final MUSIC 2ch trebuie **convenit cu Stage 2 nou**; până atunci, izolează-l în `music_stage_publish_v1.h` și raportează orice incompatibilitate, fără adapter 10→11 ascuns.
- SRC și producer/consumer pe ceasuri independente: FIFO limitat și transparent, contori de underrun/overrun. Nu insera/șterge samples invizibil ca să „aliniezi” sursele; nu face interpolare liniară de clock-sync în Stage 1 pentru a ascunde rate drift. Nu modifica ceasurile DAC din Stage 3.

## 4. Ce furnizează efectiv TIDAL / Spotify în WASAPI Exclusive

TIDAL/Spotify aleg un endpoint de redare **Windows `eRender`** și deschid un stream prin WASAPI. Pentru driverul PCM pe care îl proiectăm, ceea ce ajunge la interfața audio sunt **frames PCM interleaved L/R** și parametrii streamului negociat, nu un pachet muzical cu „dinamică suplimentară”. Driverul **nu primește automat** containerul FLAC, masterul original, metadatele artistului, setările interne TIDAL, informații despre codec sau „bit-perfect flag” garantat.

Contractul de format de păstrat la fiecare generație:

| Câmp | Sursă / obligație |
|---|---|
| `sampleRate` | rata negociată efectiv pentru instanța WaveRT |
| `nChannels` + `dwChannelMask` | stereo 2ch, FL/FR; respinge layout neașteptat |
| `wFormatTag`, `SubFormat` | PCM int sau IEEE_FLOAT; fără ghicit după `wBitsPerSample` |
| `wBitsPerSample` | lățimea containerului (16 / 24 / 32) |
| `wValidBitsPerSample` | biți audio valizi (ex. 24 în container 32) |
| `nBlockAlign`, `nAvgBytesPerSec` | validate strict cu canale/rata/container |
| stream generation, packet sequence, frame count | create de driver, monotone și coerente |
| timestamp QPC, loss/discontinuity | timp raportat corect; nu inventa precizia ceasului |
| `mode` Shared/Exclusive | numai dacă există sursă de informație **fiabilă**; altfel `UNKNOWN` |

**NOTĂ:** `AUDIO_SIGNALPROCESSINGMODE_RAW != AUDCLNT_SHAREMODE_EXCLUSIVE`. Nici rata nativă, nici volumul blocat nu demonstrează modul de acces. Nu clasifica Exclusive după `RAW` cum face driverul Music Transport din referință.

Conversie reprezentare **exclusiv la adaptor/Stage 1**, nu în driver: PCM16 signed → FP64; PCM24 packed (numai dacă este declarat și implementat) → sign extension; PCM24-valid-in-32 MSB-aligned → FP64 corect; PCM32 int → FP64; Float32 IEEE → FP64 numeric. Nu trata Float32 ca Q31 și nu confunda 24 packed cu 24-valid-in-32. Nu aplica gain, clip, dither, normalizare sau SRC în driver.

Suport minimum explicit și **real**, nu declarativ: 44.1 / 48 / 88.2 / 96 / 176.4 / 192 kHz × PCM16 și PCM24-valid-in-32. PCM32-int, Float32, 24-packed și 352.8/384 kHz se adaugă numai dacă sunt suportate corect cap-coadă; **altfel se resping explicit la negociere**. Nu declara în INF `WAVEFORMATEXTENSIBLE` acceptat dacă rendererul/bridge-ul nu poate transporta exact acel subtype.

## 5. Driver V2 — proiect separat, WASAPI ca interfață publică

**Scop:** o singură ieșire audio Windows, `Entropy Music Render V2`, selectabilă în TIDAL/Spotify exact ca un DAC, cu Shared și Exclusive funcționale. **Fără hardware DAC real; fără ASIO, Direct KS client, MME provider, SRC, DSP, Qt sau code coupling cu Stage 1.** Intern, Windows continuă să folosească WaveRT/PortCls/KS, inevitabil. Nu încerca să elimini componentele KS ale sistemului.

- Pornește de la referința Microsoft **Simple Audio Sample** (sau SYSVAD cu eliminare strictă a funcțiilor nefolosite), dar implementează transportul de samples real; un driver de exemplu care generează sunete/test tone **nu este** automat un transport audio corect.
- Instalează o identitate **nouă**, complet separată de Private Tap, Music Transport și AUX: hardware ID, service, SYS, INF, property-set GUID, protocol magic/version, nume endpoint, device interface. Nu reutiliza ringul sau starea globală a driverelor vechi.
- Virtual eRender WaveRT, stereo, mod de lucru WASAPI Shared/Exclusive la formatele confirmate. Respectă exact negocierile și erorile `IsFormatSupported`/`Initialize` ale aplicației. Un format cerut dar nesuportat **eșuează**, nu este interpretat aproximativ.
- **Clock coerent:** model per-stream cu `QPC_start`, `QPC_frequency`, rată validată și contor monotonic **64-bit de cadre**. Derivă poziția de redare din timp cu aritmetică suficient de precisă (remainder fracționar păstrat); nu rotunji mereu la milisecunde întregi, nu avansa DMA cu număr de octeți nealiniat la `nBlockAlign`, nu raporta poziție care revine în timp decât prin modulo la bufferul circular. Notificările și indexul pachetului trebuie să corespundă aceleiași poziții logice.
- **Publicarea PCM:** o singură cale de ownership activă pentru fiecare instanță. În notification/event mode, preia **doar pachetele complet scrise și confirmate**; în position-driven mode, o cale de fallback explicită. Nu citi memory încă rescrisă de client; nu publica de două ori prin `SetWritePacket` și `UpdatePosition`; nu amesteca vechiul buffer la wrap-around.
- Bridge kernel→user: ring bounded, frame/sequence/generation, format atomic, contori de pierdere și underflow, lipsă consumator raportată. Nu aștepta Qt sau Stage 1 din kernel. Când Stage 1 e oprit, endpointul poate rămâne instalat/vizibil, dar nu acumula memorie nelimitată; marchează pierderea explicit.
- **Nu promite că volume slider în TIDAL trebuie să fie prezent în Exclusive.** Verifică implementarea reală `IAudioEndpointVolume`/session volume a endpointului, dar nu adăuga volum fictiv ori procesare internă doar ca să apară sliderul. În Shared, comportamentul controalelor Windows trebuie să fie coerent.
- Driverul nu se instalează și nu înlocuiește cele trei drivere existente fără acord explicit; semnare WDK/test machine conform politicii Windows. Creează rollback/documentație de instalare separată. Nu auto-înregistra driverul la fiecare lansare Stage 1.

## 6. Interfața dintre driver și Stage 1: contract verificabil

Într-un ABI C versiunat și independent de Qt definește minimum:

```cpp
struct EntropyIngressDescriptorV2 {
    uint32_t abiVersion, structSize;
    uint64_t generation, packetSequence, firstSourceFrame;
    uint32_t frames, channels, sampleRate;
    uint32_t containerBits, validBits, blockAlign, channelMask;
    uint32_t formatTag, subFormatCode, flags; // subtype identificat complet în ABI, nu doar dacă este ambiguu
    uint64_t qpcTimestamp, qpcFrequency;
    uint64_t lostFrames, discontinuities;
};
// Payload: frames PCM ORIGINALI în formatul negociat;
// adaptorul poate furniza și FP64 planar, dar doar după conversie explicită,
// cu păstrarea identității pachetelor pentru verificarea transportului.
```

Exemplul este **schiță**, nu ABI final: creează un contract binar aliniat/versiunat cu enum-uri/subtype GUID complete și validare strictă a tuturor dimensiunilor. Contorii globali și metadatele pachetului nu trebuie să expună valori incoerente obținute în momente diferite. Nu confunda `qpcTimestamp` (captură/commit) cu un timestamp garantat exact al fiecărui sample DAC.

## 8. Acceptanță minimă — fără testomanie

**Verificare 1 — PCM determinist (offline, un singur caz per reprezentare implementată):** L/R diferite, format cunoscut, două buffer boundaries; compară bytes după packet commit cu bytes primiți în adaptor, pentru aceleași `(generation, sequence, firstFrame)`. Rezultat obligatoriu: samples identici, ordonare identică, zero dubluri/gap-uri. Verifică metadatele de rată/biți; un format neimplementat este refuzat.

**Verificare 2 — comparație live scurtă, numai după aprobarea instalării:** aceeași secvență TIDAL, format care acum sună rău, Exclusive și Shared; citește **înainte de SRC** starea negociată, contori pachete, L/R peak/RMS și Mid/Side pentru separare stereo, apoi aceeași telemetrie la ieșirea SRC. Nu presupune că Master-ul original este accesibil, nu salva muzică brută fără acord. Dacă Stage 1 primește PCM diferit între moduri, raportează diferența, **nu** inventa cauzalitatea.

**Verificare 3 — control arhitectural scurt:** Stage 1 rulează/publică fără Qt și fără Stage 2, Qt se poate închide fără oprirea audio, MIDI/CINEMA/Stage3 nu sunt pornite, niciun provider nu este hardcodat în engine. Nu rula suite exhaustive sau benchmarkuri fără cerere.

**STOP imediat** la lipsă de semnare/WDK, ambiguități de format, ABI Stage2 neconvenit, sunet Exclusive corupt, sau orice operație care ar înlocui driverul de producție. Livrează diagnosticul și fișierele obținute; nu compensa prin gain/headroom sau alte module.

## 9. Rezultatul acceptat

- `Stage1 Native Engine` **MUSIC + AUX**, FP64/192, publisher pasiv strict **2ch L/R** către noul Stage 2.
- `Stage1 Qt` separat, numai IPC + selector/discovery + telemetrie.
- `Entropy Music Render V2` este **un proiect Windows driver separat**, capabil să apară în lista TIDAL/Spotify la fel ca un DAC, cu Shared/Exclusive verificabile; nu necesită hardware audio real, dar **necesită driver/dispozitiv audio Windows instalat**.
- Zero CINEMA în Stage 1; zero modificări Stage 2/3; nicio presupunere că simpla activare Exclusive aduce automat calitate sau că schimbarea formatului transmite alte date decât PCM + metadata de stream.
