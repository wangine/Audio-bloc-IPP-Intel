Entropy StageBus V1 — Windows x64

The single shared SDK is in sdk/. C/POD wire headers are compiler-neutral; the Win32 transport implementation can be built with MinGW or MSVC. Source/DSP/Render are separate programs. This package implements Source only.

Audio: FP64 IEEE754 binary64 LE, planar, 192000 Hz, 1024 frames. MIX_CINEMA10_V1: MUSIC_L, MUSIC_R, CINEMA_L, CINEMA_R, CINEMA_C, CINEMA_LFE, CINEMA_SL, CINEMA_SR, CINEMA_BL, CINEMA_BR. LRC_CINEMA11_V1 additionally inserts MUSIC_CX at index 2. Four SPSC slots are transport capacity, not preroll. Source capture policy remains R10: preroll 8192, target 16384, capacity 524288, capture capacity 131072 frames.

Session discovery: state/StageBusSession.json contains the exact 256-byte session header in base64. Only EXTERNAL sessions accept an external consumer. Open validates the entire contract, layout hash, UUID, rate, strides, producer process and PID claim. Standalone already owns its one consumer. Owner handoff requires DISARM, audio quiesce, a new UUID and sequence 1. V1 stream_epoch is 1; restarting an epoch requires a new session. Do not reset or reuse indices while a peer is attached. Peer death is a fault, never a different audio route.

Shared offsets: session 0..255; audio write 256, read 320; producer heartbeat 384, consumer heartbeat 448; request write 512, read 576, request payload 640 (120 bytes); duplicate-response write 768, read 832, payload 896 (128 bytes); ready 1024, fault 1088; Source control write 1152, read 1216, payload 1280 (64 bytes). Each counter occupies its own 64-byte cache line. Audio slots start at 4096. Each slot contains a 128-byte block header then channel planes of 8192 bytes. Stride is 128 + channels*8192. Reserved fields are zero. No pointers, Qt objects, strings, atomics or C++ objects cross the mapping.

Source control is one SPSC slot, produced by Source's control worker. trySendSourceControl refuses an unread slot; the controller retains/coalesces the latest pending desired snapshot locally. The consumer reads it with tryReceiveSourceControl on its control worker and passes its adopted manual mute mask into subsequent FrameRequests. Use a monotonic merged control revision, at least the received source_revision. SRC IDs are capability IDs of the original loaded DLL, never combo-box positions. Engine changes/rebinds are Source's responsibility. A desired MUSIC binding revision may precede valid source audio; actual music_session_revision is carried in each audio block. Source Save waits for external mute adoption and records applied SRC identities.

Render owns nominal cadence and requested program snapshots. There is at most one outstanding FrameRequest. It includes required_inputs from R10 AppliedProgramBlock OR get_required_inputs, music_program_active from projectSaveRequiresMusicAdoption, analyze_music_final, manual/effective mutes, confirmed hardware_armed, output contributors and program/project revisions. Source does not infer these from the UI. Startup MUSIC is exact Music Transport; no automatic Virtual Cable fallback. Program exclusion uses required_inputs and activation, preserving manual mutes. Frame first_frame=(block_sequence-1)*1024.

tryPublish/tryConsume are nonblocking. Reserve a writable slot before polling Source FIFOs. Consumer copies before releasing its index. Empty means no block; unavailable source planes are explicit zero with validity metadata. All-zero valid audio is not an underrun. Identical repeated requests produce a metadata-only acknowledgement via tryReceiveResponse, never a second source read or audio publish. A conflicting snapshot for the same sequence faults the session. The acknowledgement identifies an already-produced block; it is not new audio. Backpressure and protocol failures never overwrite data.

Heartbeat QPC frequency is negotiated in the session, refreshed every 250 ms; peer/request liveness is 1000 ms. Handshake/open deadline is 5000 ms on the consumer control worker. Source may remain WAITING while no external owner is attached. Sink callbacks never wait for handshake or another process; they only consume already-validated complete blocks. File discovery, OpenProcess/peerAlive, mapping lifecycle and recording belong to control/IPC workers. Original R10 high-resolution waitable timers pace the standalone demand harness; no Windows mixer or secondary SRC connects stages.

Validation covers fixed lengths, canonical offsets, bounds, hashes, identities, masks, sequence/frame arithmetic, reserved fields, and process/session lifecycle. Mapping ACL grants the current Windows user only. Audio publication/read uses Windows Interlocked acquire/release barriers. Each transport object must be quiescent before close/reset. Separate Source control, request, response and audio lanes each have one producer and one consumer.

Build the portable SDK with CMake from sdk/ (C++17, advapi32). The native audio DLLs are not part of the SDK and are not recompiled. Layout conformance and command evidence are in candidate-stage1/evidence/stage1. Header and contract SHA256 are fixed in the package manifest. No Stage 2 or Stage 3 implementation is included.

External identity operations (MUSIC bind, Load, Retry, owner handoff): Render must DISARM, send and consume a current-session DISARM block, refresh its heartbeat, then stop issuing demand. Within the 1000ms freshness window the operator explicitly confirms DISARM and stopped demand. Source pauses its audio worker and rejects unknown/stale/faulted/ARMED status or a pending request before applying the change; it stays quiescent through the operation. Render must not issue another request while this confirmed control lease is held. Reattach only to the published new UUID after owner handoff. An unattached/faulted external owner cannot authorize changes; DISARM and stop Render, then restart Source. Source never infers hardware state from missing/stale data. Physical Render acknowledgement and DAC lifecycle remain Stage3 integration tests, NOT RUN here.
